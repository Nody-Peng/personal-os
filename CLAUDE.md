# Personal OS

Single-owner personal platform (daily check-ins, AI channel publishing checklist, reading, learning backlog). Product spec: `docs/SPEC.md` (Traditional Chinese). UI copy is Traditional Chinese.

## Stack & commands

- Next.js 16 App Router + Payload 3 embedded + Postgres (`@payloadcms/db-postgres`), Tailwind v4, Phosphor icons. Deploy: Vercel + Supabase.
- Local DB: `npm run db:local` (embedded Postgres on 54322). Dev: `npm run dev`. Tests: `npm run test:int` (needs local DB). Also `npm run lint`, `npx tsc --noEmit`.
- Payload reference: `.claude/skills/payload/SKILL.md`.

## Conventions

- **Days** are Taiwan-local `YYYY-MM-DD` strings with a **04:00 day boundary** (`src/lib/day.ts`, `logicalDay()`); never use `Date` objects or Payload `date` fields for days.
- **Access**: every private collection uses `authenticated`. Frontend pages call `requireSession(path)`; server actions call `requireActionSession()` and pass `user` + `overrideAccess: false` to the Local API.
- Server actions live in `src/app/(frontend)/actions.ts`, whitelist and clamp every input, and return `ActionResult`. Validate days/months with `isDay`/`isMonth` (real calendar dates), not the bare patterns. Save "the one row for this key" (a day log, a week or month note) with `upsertOne` (`lib/upsert.ts`), which survives two saves racing to create it.
- Option lists shared by schema and UI are in `src/lib/options.ts`.
- **Journal**: daily IMPORTANT items (max 3/day) and weekly to-dos are one `tasks` collection (`src/lib/tasks.ts`); unfinished IMPORTANT items are migrated with `moveTaskToNextDay` (original keeps status `migrated`; one transaction, `migratedFrom` is unique, and a migrated original can't be ticked again). 早/午/晚 are day-only checklists (`daily-logs.morningItems`/`noonItems`/`eveningItems`, `lib/dayParts.ts`), never counted in stats: a day counts as recorded only per `isRecordedLog` (`lib/dailyLog.ts`). Journal server actions live in `src/app/(frontend)/journal-actions.ts`.
- **Rich text** (task bodies, daily note, week/month reviews) is BlockNote JSON stored in Payload `json` fields, edited with `components/editor/BlockEditor` (client-only, autosaves). Use `lib/blocks.ts` to read plain text. When `initial` comes from a server page, also pass `renderedAt={renderStamp()}`: `lib/noteCache.ts` then keeps back/forward (and a page opened before a save landed) from showing, and re-saving, stale content. Client state seeded from server props (e.g. `DayLogProvider`) uses the same `withLocal` / `rememberLocal` / `useRenderStamp`. Every editor takes uploads (`allowUploads`); pass `templateKind` (`day` / `week` / `page`) to offer `editor/TemplateBar` while the note is empty, and `editorHandle` to replace its content from outside. A failed save is retried (2 s → 30 s backoff, and when back online) and closing the tab with unsaved text asks first; `updatePage` returns the server's `savedAt`, which `noteCache` uses to tell a page render made before that save (e.g. the re-render of a revalidating action, cached without being mounted) from a newer one. Pictures open full screen in `editor/ImageLightbox` (double-click, or ⤢ in the toolbar). Editor messages (`reportNoteError` / `notes:info` events) show through `components/Toast` (`EditorToasts` in the (app) layout; `NotebookShell` shows its own).
- **Search** (Ctrl/⌘ K, `search-actions.ts`) covers notebook pages and the journal: daily logs, tasks, week and month notes each keep a read-only `plainText` (`fields/searchText.ts` hook, text from `lib/searchText.ts`). The (app) layout mounts one `components/search/GlobalSearch` (open it elsewhere with `openSearch()`); `NotebookShell` has its own.
- **Habits** are a `habits` collection (max 4 active; archive instead of delete so history stays); a day stores ticked habits in `daily-logs.habitsDone`. Use `habitIdsOf` / `habitsForPeriod` from `lib/queries.ts`.
- **Week themes** live on each week note (`weekly-reviews.theme`); the current week's theme is mirrored as idea status `selected` (`lib/weekThemes.ts`, `getCurrentTheme`).
- **Notebooks** (`notebooks` + `note-pages`, `src/lib/notes.ts`): Notion-like pages nested via `parent`, BlockNote JSON in `content` with a `plainText` copy (set by the collection hook) for search. A page's `kind` is `page`, `board` (a todo database) or `item` (a board card: `status`, `startDate`/`endDate`, `parentItem`; parent = its board). Items are hidden from the sidebar tree (and can't be moved there or hold pages); boards load through `lib/boardStore.ts` (versioned: a load that raced an optimistic edit reloads) and cards open in the side peek (`?peek=<id>`, `board/ItemPeek`). A page's look (`font`, `smallText`, `fullWidth`, `locked`) and `favorite` are set from `notebooks/PageMenu`; `duplicatePage` copies a subtree in one transaction and remaps sub-page/board blocks in the copied content. Deleting uses Payload's built-in trash (`trash: true`, `deletedAt`); a page and its subtree share one `deletedAt` so they restore together. `templateFor` marks a page as a template (••• → 用作範本). Saving content keeps the replaced version in `page-snapshots` at most every 10 minutes (50 per page, `keepSnapshot`; ••• → 版本紀錄 restores through the editor handle). Backlinks (`getBacklinks`) find link-mode `pageLink` blocks with a `jsonb_path_exists` query, so nested blocks count. Opening a notebook goes to `notebooks.lastPage` (set by `rememberOpenedPage` when a page mounts), else the last edited page. The page title and the text behave as one document: Enter splits the title into a new first line, ↓ goes down, ↑ / Backspace at the top go back (`notebooks/titleKeys.ts`, `editor/titleNavigation.ts`, `EditorHandle.enterFromTitle` / `focusStart`, `onLeaveTop`; the card peek too). Page operations are in `lib/notebookOps.ts` (taking a `Session`), shared by those server actions and the MCP endpoint. Content saves go through `writePageContent`: `note-pages.contentRev` goes up with every content save (collection hook), and an editor saves against the revision it has (`BlockEditor` `revision`); a refused save is merged block by block (`lib/blockMerge.ts`) and saved again, and an idle open page picks up changes made elsewhere (`syncPage`, quietly via `EditorHandle.apply`). Server actions live in `src/app/(frontend)/notebook-actions.ts`; the notebook view (`/notebooks/[id]/[pageId]`) has no AppNav and keeps its tree in client state (`NotebookShell`), with `lib/noteCache.ts` guarding against stale back/forward payloads.
- **Editor schema** (`components/editor/schema.tsx`): default blocks + callout, toc, pageLink (`mode` child = sub-page created in the text / link = any page), board (a link outside a notebook), bookmark (`blocks/BookmarkBlock`: metadata fetched once by `getLinkPreview` in `link-actions.ts` and stored in the block; `lib/linkPreview.ts` asks as Slack's, then Facebook's, link unfurler since many sites only answer those), embed (`blocks/EmbedBlock`; `lib/embeds.ts` maps YouTube/Maps/Docs/Figma… to frame URLs; any other site is checked with `getFramePolicy` first and, if it refuses frames, offers a bookmark instead of an empty box), and `@blocknote/xl-multi-column` columns (GPL-3.0; fine for this private site). Notebook-aware blocks read `NoteContext`. The slash menu uses Notion's Taiwan names and aliases (文字, 待辦清單, 項目符號清單, 引言…; `editorDictionary`) in Notion's order (`MENU_ORDER`); items are ranked exact → prefix → contains and kept grouped (`rankItems`). `/` and `:` only open where a word starts (`editor/menuTriggers.ts`: not in 1/2, 10:30, and/or) and a menu closes when nothing matches, so Enter keeps working. /頁面 creates the sub-page and opens it (`NoteContext.openPage`). Link-to-page, bookmark and embed pickers open and take the focus only when just inserted (`blocks/freshBlock.ts`); found empty later they are a placeholder, and a click elsewhere drops an empty page link or folds the others back. Enter on an empty nested list item outdents it; `notionShortcuts` makes `> ` a toggle (quote is `" `) and ```` ``` ```` a code block, and its Enter (`editor/toggleEnter.ts`) keeps a toggle's children with it (open → new first child, closed → new toggle below). An open toggle whose last child isn't text leaves a strip below it (styles.css) that adds a line when clicked, as does the space under a short column (`lineBelow` in `blockSelection.ts`). Pasting a lone URL asks keep / bookmark / embed (`editor/PasteUrlMenu`); `:` opens the emoji grid (`editor/emojiItems`); the ⋮⋮ menu is `editor/BlockMenu` (duplicate, copy block link → `#block-<id>`). Export/import (Markdown, HTML) is `lib/exportNote.ts`.
- **MCP** (`/api/mcp`, `lib/mcp/`): a stateless Streamable HTTP MCP server for Claude, on only when `MCP_TOKEN` (≥32 chars) is set; requests need `Authorization: Bearer <token>` (`lib/secrets.ts`, constant-time). It acts as `MCP_USER_EMAIL` or the first account, through the normal access rules. Tools (`lib/mcp/tools.ts`) read and write notebook pages as Markdown (`lib/mcp/markdown.ts`: plain mdast/GFM code, no DOM — BlockNote's own converters need one, and jsdom broke the function on Vercel), read the journal and book highlights, and add Important items / weekly to-dos (`lib/taskOps.ts`, `lib/searchCore.ts`). Nothing deletes for good: `trash_page` uses the trash and `replace_page_content` forces a snapshot first. `upload_image` takes a base64 picture (≤ 3 MB, Vercel's body limit) and stores it in `media` as a scaled, compressed JPEG (`lib/mediaOps.ts`, sharp); a page then shows it with a `![alt](/api/media/file/…)` paragraph, which also keeps the daily cleanup from deleting it. Tested over an in-memory MCP client in `tests/int/mcp.int.spec.ts` (Node environment: Payload's upload checks reject jsdom's Buffer; vitest aliases `server-only`).
- **Code blocks** replace BlockNote's `codeBlock` render with `blocks/CodeBlock` (language picker + copy at the top right, default Bash). Languages are listed in `editor/codeLanguages.ts`, and each needs a grammar in `editor/codeHighlighter.ts` (Shiki, JS regex engine, `@shikijs/langs`; the precompiled grammars mis-tokenize).
- **Page icons** are an emoji, `ph:<name>:<colour>` (a Phosphor icon, `lib/noteIcons.ts`) or an uploaded picture's `/api/media/file/…` URL, all validated by `cleanNoteIcon`. Always render them with `notebooks/NoteIcon` (emoji use the shared `--font-emoji` stack: Apple, then Noto Color Emoji from `layout.tsx`). The picker's emoji list is generated by `npm run emoji` (emojibase-data, zh-Hant names).
- **Block selection** (`components/editor/blockSelection.ts`): Notion-style box select from the margins (an ancestor with `data-block-select-zone` widens the area). The selection is a ProseMirror `BlockSelection` (a run of sibling blocks); while it is active, keys go to a hidden `.block-select-sink`, and `BlockMenu`'s drag handle widens BlockNote's one-block drag to all selected blocks. While typing, ⌘A selects the block's text, then every block; ⌘D duplicates the block. Box select leaves BlockNote's strip under the last block (click = new line) and column resize edges alone.
- **Media**: `media` upload collection, private. Production uses Supabase Storage through `@payloadcms/storage-s3` (`S3_*` env vars; browsers upload directly with signed URLs, downloads redirect to signed URLs); without `S3_BUCKET` files go to `./media`. The plugin is always registered (`enabled` + `alwaysInsertFields`) so the schema doesn't depend on env. Upload with `lib/uploadMedia.ts` (shrinks photos to JPEG ≤ 2400px and always converts WebP, which Payload would re-encode lossily and orphan the original; PNGs such as screenshots keep their size and are re-compressed losslessly with oxipng in `lib/pngOptimizer.worker.ts`; page icons pass `{ maxSide: 512, keepAlpha: true }`). Files nothing refers to are cleaned up by the daily job: any `/api/media/file/…` string anywhere (trash and snapshots included) counts as a use.
- **Daily job**: Vercel Cron calls `/api/cron/daily` (`vercel.json`; needs the `CRON_SECRET` env var) → `lib/dailyJobs.ts`: purges trash older than `TRASH_DAYS`, drops snapshots without a page, marks unused media (`unusedSince`) and deletes it after 7 more unused days. Its queries also keep the free Supabase project from pausing. The database is backed up daily by `.github/workflows/backup.yml` (encrypted pg_dump artifact: the repo is public).
- **Journal book** (年度頁 → 匯出 PDF): `/print/journal?from&to&…` (outside the (app) layout; options parsed and clamped by `lib/journalPrint.ts`, ≤ 366 days) loads everything in a few queries (`lib/journalBook.ts`), renders the book on the server (`components/journalPrint/JournalBook`: cover, title page, contents, per month an opener + habit tracker/energy curve + a page per day + a week page after each Sunday + the month review, summary, letter page, back cover; `BookBlocks` prints BlockNote JSON, pictures as polaroids; `BookCharts` are SVG in mm), and `PagedBook` paginates it in the browser with Paged.js, then `window.print()` saves the PDF. Paged.js is aliased to its prebuilt bundle in `next.config.ts` (its source imports `es5-ext/string/#/contains`, which bundlers misresolve); it waits on animation frames, so a hidden tab pauses the layout. The stylesheet (`bookCss.ts`: `@page` rules, named pages, running heads, `target-counter` page numbers) has its own paper palette and plain hex tints, since Paged.js re-parses it; text sits on ruled lines (`--line`), so vertical spacing is in whole lines. Fonts (Iansui / LXGW WenKai TC, Caveat) come from Google Fonts; `document.fonts.load(font, text)` fetches just the character slices the book uses before layout. Stats are `lib/journalStats.ts`.
- **Bookshelf** (`/journal`): journals and notebooks share `components/books/BookCover` (colours and CSS patterns in `lib/options.ts`, styles under `.cover-cloth` in `styles.css`). `BookLink` plays the open-the-book animation via `BookOpenProvider` in the root frontend layout.
- **E-books** (`/books`, `components/reader/`): `books` is a private EPUB upload collection stored like media (S3 prefix `books`). Title/author/cover are read in the browser with epub.js when added (`importEpub`); the cover is uploaded to `media` and kept as a `coverUrl` string (the daily cleanup only keeps media referenced by URL). The reader (`/books/[id]`, no AppNav, client-only via `ReaderLoader`) caches the EPUB and its page index in Cache Storage (`loadBook.ts`), saves `cfi`/`progress`/`lastReadAt` (reaching the end sets `finishedAt`), `bookmarks` and `highlights` (JSON, drawn with epub.js annotations) through `book-actions.ts`, and has its own palette (`--r-*` vars, `reader/settings.ts`). Categories are the `book-shelves` collection (`books.shelves`, hasMany); reading status (未讀/在讀/讀完) is derived by `statusOf` in `lib/books.ts`. Saves made while leaving the reader are awaited by the library through `reader/readingSync.ts`. Read aloud (`readAloud.ts`, `sentences.ts`) highlights the sentence with the CSS Custom Highlight API and has two voice kinds: the browser's Web Speech API (free, one utterance per sentence) or cloud voices — Azure / Gemini through `/api/tts` (`lib/ttsServer.ts`, keys only on the server; Gemini WAV is encoded to MP3 in `lib/audioEncode.ts`). Cloud audio comes in fixed pieces per chapter (`CHUNK_CHARS`: Azure ~300 characters; Gemini ~70, since it takes ~5 s plus ~0.08 s a character), fetched `PREFETCH` pieces ahead, plays in an `<audio>` element (lock screen + Media Session) and is cached per device in Cache Storage (`reader/cloudSpeech.ts`). While the page is hidden (screen off, another app) epub.js can't lay out pages (it waits for animation frames), so the next chapter is read from the book file (`section.load`, the same sentence numbering), page turns wait until the page is shown again, the spot is saved every 30 s through `onPosition`, and the next chapter's first piece is fetched ahead. Browser voices can't do this on phones: Chrome for Android stops the Web Speech API whenever the app has no visible window (`tts_android.cc`, `CanSpeakNow`), so a browser voice resumes its sentence when the page is shown again (`onNotice` says why). `TTS_MOCK=1` (development only) answers with a tone. The sleep timer can stop at a chapter end (`continueAfterChapter`).
- **Login** is the custom `/login` page (Payload REST login); `/admin/login` remains for the admin. Use `safeRedirect` (`lib/safeRedirect.ts`, re-exported from `lib/session.ts`) for any post-login target.
- **Security**: each production boot enables RLS on every `public` table (`onInit` in `payload.config.ts`; Payload connects as the owner, so no policies are needed). The CSRF allowlist is opt-in via `NEXT_PUBLIC_SERVER_URL`; never set `serverURL` (it makes media URLs absolute). Anything the server fetches for a user-given URL goes through `lib/linkPreview.ts` (public addresses only, checked when connecting).
- The task side panel is URL-driven (`?task=<id>`, `lib/useTaskPeek.ts`); the month calendar opens week notes with `?week=<monday>`. Open/close URL panels with `lib/panelHistory.ts` (closing steps back over the entry it opened). Panels that close on Esc skip it while `escapeHandledElsewhere()` (`lib/escape.ts`); mark anything that handles its own Esc with `data-own-escape` (`="focus"` for pickers inside the text: they count only while focused). With text selected, Ctrl/⌘ K is BlockNote's link button, not search. `fixed` popovers render in a portal (a blurred sticky header would otherwise be their containing block).
- **Channel** (`/channel`, nav 頻道): the weekly publishing checklist for the AI channel — an AI 報報 every day (a slot per weekday; the day page marks today's), an AI 教學 and a 知識型 video, 4 shorts cut from them (`CHANNEL_SLOTS` in `lib/options.ts`). Each slot is a tick plus one line of text, stored as JSON on the week note (`weekly-reviews.channel`, cleaned by `cleanChannel` in `lib/channel.ts`; the notes are part of the week's search text). `components/channel/ChannelChecklist` saves the whole week through `saveChannelWeek` (ticks at once, typing after a pause) and appears on `/channel` (any week: 上一週/本週/下一週, and a list from two weeks ahead back eleven) and on the day page for that day's week. Each week also has a free note, `weekly-reviews.channelNote` (BlockEditor target `channel`), on `/channel`.
- **TOEFL is archived**: `/toefl` is a read-only view of old `toefl-scores` (not in the nav); the day page, stats and actions no longer read or write `daily-logs.toeflMinutes`/`toeflSkills` or the settings' exam fields, which stay in the schema for the history (`isRecordedLog` still counts old TOEFL minutes). Scores use the new (Jan 2026) 1–6 scale in `src/lib/toefl.ts`; never store 0–120 scores.
- **Schema changes**: run `npm run generate:types`, then `npm run payload migrate:create <name>` and commit `src/migrations/*` (production applies them via `prodMigrations`).
- **Design**: follow `.claude/skills/minimalist-ui` (warm monochrome, 1px `#EAEAEA`-style borders, radius 8/12, one accent `--color-accent` for interaction and chart marks, pastel pairs only for small semantic tags). Tokens are in `src/app/(frontend)/styles.css`, redefined for dark under `[data-theme='dark']` (`lib/theme.ts`: 跟隨系統/淺色/深色 per device, set before paint by `THEME_SCRIPT`), so never hard-code a colour: text on an ink/accent fill is `text-on-ink`, dialog backdrops `bg-scrim`, icon colours `--color-icon-*`; the editor gets `theme={useResolvedTheme()}` and code uses Shiki's light/dark pair. Phones: no sideways page scroll at 375px, ≥40px tap targets (the editor's ⋮⋮ handles are hidden there; insert / move / duplicate / delete sit in BlockNote's toolbar above the keyboard, `editor/MobileBlockButtons`, and a tap on a link places the caret), `md:` for desktop density; motion classes (`pop-in`, `page-in`, `check-in`, `sheet-in`…) all stop under `prefers-reduced-motion`. Charts follow the dataviz rules: hand-rolled SVG at real pixel width (`useElementWidth`), hover tooltips, text never in series color.
